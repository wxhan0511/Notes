# 单片机运行c++程序

## 生成 .lib（GNU ar 格式

1. 生成 .lib（GNU ar 格式）
arm-none-eabi-g++ -c .\ThirdParty\GCGTMain\src\GCGTMain.cpp -I.\ThirdParty\GCGTMain\include -mcpu=cortex-m3 -mthumb -mfloat-abi=soft -Os -ffunction-sections -fdata-sections -o .\ThirdParty\GCGTMain\lib\GCGTMain.o
<!-- arm-none-eabi-g++
ARM 交叉编译器
C++ 编译器（如果是 C 用 arm-none-eabi-gcc）
专门给 STM32 ARM 内核 编译代码
运行在 Windows，输出 ARM 指令集 -->
<!-- -c
只编译，不链接
只生成 .o 目标文件
不生成可执行文件
制作静态库必须加 -c -->
<!-- -mcpu=cortex-m3
编译目标：ARM Cortex-M3
你 STM32 是什么核就填什么
M0 → cortex-m0
M4 → cortex-m4
M7 → cortex-m7 -->
<!-- 所有 ARM 编译器参数，只要是 -m 开头，都表示：给【目标硬件 / CPU】设置选项。 -->
<!-- -mthumb
使用 Thumb 指令集
STM32 必须加
代码更小、执行更快 -->
<!-- -mfloat-abi=soft
软浮点（纯软件计算浮点数）
Cortex-M3 没有 FPU，必须用 soft
如果是 M4/M7 可以用 hard -->
<!-- -Os
优化目标：最小体积
适合嵌入式、节省 Flash
常用优化：
-O0 不优化（调试）
-O2 速度优先
-Os 体积优先 -->
<!-- -ffunction-sections
每个函数放在独立段
链接时可以删除未使用函数
静态库、固件裁剪必备 -->
<!-- M3 无 FPU → 必须 soft -->
<!-- 编译器不知道你用哪个函数
链接器只能删 “段”，不能删 “函数”
所以必须让一个函数 = 一个段
才能做到：用多少，留多少 -->
arm-none-eabi-ar rcs .\ThirdParty\GCGTMain\lib\GCGTMain.lib .\ThirdParty\GCGTMain\lib\GCGTMain.o

<!-- 1. arm-none-eabi-ar
ARM 架构专用的静态库打包工具
来自 ARM GCC 工具链
功能：把 .o 目标文件 → 打包成 .a/.lib 静态库
只能用于 STM32 / ARM 嵌入式，不能给 Windows 使用 -->
<!-- rcs（三个关键参数，最重要！）
这是 ar 工具的 3 个参数合写，分开解释：
r = replace
如果库已经存在，替换旧的 .o
没有就添加进去
c = create
库不存在就自动创建
不会报 “文件不存在” 错误
s = index
给静态库生成 符号表索引（symbol index）
让链接器更快找到函数
不加 s 可能会报 undefined reference
3. .\ThirdParty\GCGTMain\lib\GCGTMain.lib
输出的静态库文件名
虽然后缀是 .lib
但本质是 GNU .a 格式
可以直接给 STM32CubeIDE / Keil ARMClang 使用
4. .\ThirdParty\GCGTMain\lib\GCGTMain.o
要打包进库里的 目标文件
就是你上一条 arm-none-eabi-g++ -c 生成的
可验证库里有符号：
arm-none-eabi-nm .\ThirdParty\Demo\lib\xxx.lib -->
## 准备 C 包装层

```c

# ifndef GCGTMAIN_C_H

# define GCGTMAIN_C_H

# ifdef __cplusplus

extern "C" {

# endif

int GCGT_RunOnce(void);

# ifdef __cplusplus

}

# endif
# endif

```

## C++ 包装实现

```c
#include "GCGTMain.h"
#include <vector>

static double MeasureCb(int) { return 0.0; }
static bool WriteCb(int, int, int, int, bool) { return true; }

extern "C" int GCGT_RunOnce(void)
{
    GCGTMain::GCNGTClass algo;
    std::vector<double> inputLv(30, 0.0);
    std::vector<int> inputReg(15, 0);
    std::vector<int> outReg;

    algo.GammaTuning_Enhance("GC7274", 2.2, inputLv, inputReg, outReg, &MeasureCb, &WriteCb);
    return (int)outReg.size();
}
```

## 在 CMake 里链接库并启用 C++ 链接

```c
add_library(GCGTMain STATIC IMPORTED)
set_target_properties(GCGTMain PROPERTIES
    IMPORTED_LOCATION ${CMAKE_SOURCE_DIR}/ThirdParty/GCGTMain/lib/GCGTMain.lib
)

target_include_directories(build.elf PRIVATE
    ${CMAKE_SOURCE_DIR}/ThirdParty/GCGTMain/include
)

# 把包装层 cpp 编进最终目标（路径按你实际放置位置）
target_sources(build.elf PRIVATE
    ${CMAKE_SOURCE_DIR}/ThirdParty/GCGTMain/src/GCGTMain_c.cpp
)

target_link_libraries(build.elf PRIVATE GCGTMain stdc++)
set_target_properties(build.elf PROPERTIES LINKER_LANGUAGE CXX)
```

## 在程序里调用

```c
#include "GCGTMain_c.h"
volatile int gtgt_ret = GCGT_RunOnce();
```

## 重新配置与编译

```c
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=arm-none-eabi-gcc -DCMAKE_CXX_COMPILER=arm-none-eabi-g++
cmake --build build -j
```

## 解释
<!-- STM32（ARM Cortex‑M）工程：
一、绝对不能用 Windows / Visual Studio / MSVC 编译出来的 .lib 静态库！
原因：
CPU 架构不同
PC：x86 / x64
STM32：ARM Cortex‑M
→ 指令集完全不兼容
格式完全不同
MSVC .lib = COFF 格式（Windows 专用）
STM32 需要 = ELF / GCC 格式（.a）
→ 链接器直接报错，无法识别
系统库不同
PC 库依赖 Windows API，STM32 根本没有。
STM32 工程不能拿 Windows/MSVC 的 .lib 直接用。
你要的是 ARM 交叉编译产物，本质应是 GNU 静态库（通常 .a）。
你可以把 GNU 静态库重命名成 .lib 来用，但格式必须是 GNU ar 归档，不是 MSVC COFF import lib。
<!-- 二、STM32 能用的静态库只有一种
必须是 ARM 交叉编译器编译出来的 .a 静态库
编译器必须是下面任意一种：
ARM GCC
ARMClang
Keil ARMCC
文件格式：GNU ar 归档（.a）
虽然 格式必须是 ARM GCC .a
但你可以把文件名改成 .lib 给 Keil 用-->
<!-- 四、最常见的错误
把下面这些库放进 STM32 工程：
Visual Studio 编译的 .lib
MinGW x64 编译的 .a
Linux x64 编译的 .a
→ 全部报错：文件格式无法识别 -->
